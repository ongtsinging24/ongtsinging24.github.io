1A-MSDU 在 MPDU 中的位置

A-MSDU 的「聚合」發生在單一 MPDU 內部。整個 A-MSDU 共用一個 MAC header、一組加密參數 (一個 PN) 和一個 FCS。

MAC HeaderFC / Dur / A1~A3 / SeqCtl
QoS Ctlbit 7 = 1
CCMP Hdr8 B，含 PN
Frame Body = A-MSDU
subframe 1subframe 2…
MIC8 B
FCS4 B

一個 MPDU，一個 PN，一個 FCS。

判斷是否為 A-MSDU 的方法：

  • 必須是 QoS Data frame (subtype 帶 QoS)
  • QoS Control 的 bit 7 = "A-MSDU Present"

2A-MSDU body 的格式 (subframe)

DA6 B
SA6 B
Length2 B，big-endian
MSDU0~2304 B = LLC/SNAP (8) + payload
Padding0~3 B

前三個欄位合起來是 14 bytes 的 subframe header，長得跟 Ethernet header 一樣。

格式上的重點：

  1. Length 是 MSDU 的長度，不包含 14 bytes 的 subframe header 和 padding，使用 network byte order。
  2. Padding：每個 subframe 的總長度 (14 + Length) 要補到 4 bytes 對齊。最後一個 subframe 不補。
    pad = (4 - ((14 + len) & 3)) & 3
  3. MSDU 內容通常以 RFC1042 LLC/SNAP 開頭： 
    AA AA 03 | 00 00 00 | EtherType(2)   → 例如 08 00 = IPv4
DSAP SSAP Ctrl | OUI  |
  4. Mesh A-MSDU (802.11s)：subframe header 之後多一個 Mesh Control 欄位 (6/12/18 B)，而且 Length 會把它算進去。
  5. 大小上限：HT 為 3839 / 7935 bytes。VHT/HE/EHT 的 A-MSDU 受 MPDU 長度上限約束 (3895 / 7991 / 11454)。
  6. 位址語意：subframe 內的 DA/SA 是「端到端」位址，跟 MAC header 的 A1/A2 (RA/TA) 是兩回事。在 MLO 下，A1/A2 是 link address，subframe DA/SA 則是 MLD address。

順序的意義：reorder、replay check 和解密都是以 MPDU 為單位。所以這些步驟要在 de-amsdu 之前做，每個 A-MSDU 只做一次，拆出來的所有 subframe 共用同一個 PN 和 seq num。

4如何拆 subframe

Kernel 的實作在 net/wireless/util.c: ieee80211_amsdu_to_8023s()。邏輯簡化後如下：

/* skb->data 已經指向 A-MSDU body：MAC header、IV、MIC 都已移除 */
while (remaining > 0) {
    if (remaining < 14) goto drop;                 /* header 不完整 */

    struct ethhdr *eth = (void *)skb->data;        /* DA|SA|Len 跟 ethhdr 長得一樣 */
    u16 len = ntohs(eth->h_proto);                 /* 這裡的欄位其實是 Length */
    u16 sublen = 14 + len;

    if (sublen > remaining) goto drop;             /* 長度欄位超出邊界 → 整包丟 */

    bool last = (remaining <= sublen + 3);         /* 剩下的只是 padding */
    u8 pad = last ? 0 : (4 - (sublen & 3)) & 3;

    /* 取出這一個 MSDU：最後一個直接重用原 skb，其他的複製或 clone 出新 skb */
    struct sk_buff *frame = last ? skb : copy_or_clone(skb, sublen);

    /* 安全性 / 合理性檢查 (見第 6 節) */
    if (!check_sa_da(eth, iftype, ...)) { drop(frame); continue; }

    convert_to_8023(frame);                        /* 第 5 節 */
    __skb_queue_tail(list, frame);

    skb_pull(skb, sublen + pad);
    remaining -= sublen + pad;
}

實作上的細節：

  • 任一 subframe 的長度不合法時，整個 A-MSDU 都要丟掉。原因是後續 subframe 的邊界已經無法信任。
  • 為了避免複製，kernel 會優先用 skb_clone 加上 pull/trim，或者在 page frag 上直接切。payload 很大時 (例如 11K A-MSDU) 這點很重要。
  • 拆分之前就要把 A-MSDU 的 PN 和 TID 記好。拆出來的每個 subframe 都屬於同一個 seq/PN，不能再各自做一次 replay check，否則第二個以後的 subframe 都會被當成 replay 丟掉。

灰色的 8 bytes (Len + SNAP 前 6 B) 被移除。

判斷規則 (ieee80211_is_valid_amsdu / ieee80211_get_8023_tunnel_proto 一帶的邏輯)：

  • 如果 SNAP 是 AA AA 03 00 00 00 (RFC1042)，且 EtherType 不是 IPX (0x8137) 或 AARP (0x80F3)，就拿掉 SNAP，產生 Ethernet II。
  • 如果 SNAP 是 AA AA 03 00 00 F8 (Bridge-Tunnel)，也拿掉 SNAP，產生 Ethernet II。
  • 其他情況 (例如純 802.2 LLC) 保留 LLC，產生 802.3 格式的 frame，原本 type 的位置放 length。

在記憶體上，只要把 DA 和 SA 往後搬 8 bytes 蓋掉 LLC/SNAP，再 skb_pull(8)，EtherType 就自然落在正確位置：

memmove(skb->data + 8, skb->data, 12);   /* DA+SA 往後搬 */
skb_pull(skb, 8);                         /* 丟掉前 8 bytes */
/* 現在 data = DA | SA | EtherType | payload */

6安全性檢查 (FragAttacks 之後必須做)

CVE-2020-24588 (A-MSDU injection)：傳統 CCMP 的 AAD 沒有保護 QoS Control 的 A-MSDU Present bit。攻擊者可以翻轉這個 bit，讓接收端把一個普通 MSDU 誤解析成 A-MSDU，進而注入任意封包。

緩解方式：

  1. 支援 SPP A-MSDU (RSN Capabilities 宣告)。雙方都支援時，A-MSDU Present bit 會被放進 AAD 受到保護。
  2. 如果第一個 subframe 的 DA == AA AA 03 00 00 00，代表它很可能是普通 MSDU 被誤判 (前 6 bytes 其實是 LLC/SNAP)，應直接丟棄。mac80211 的 ieee80211_rx_h_amsdu 有這項檢查。
  3. 非 mesh 情況下，RA 是 multicast 的 A-MSDU 要丟棄。
  4. 依介面模式檢查 subframe 的 SA/DA。例如 AP 端在非 4-addr 模式下，subframe 的 SA 應該等於傳送端 STA 的位址，否則就是在偽造來源。

7上報 kernel network stack

/* 對每個拆出來的 802.3 frame */
skb->dev = sdata->dev;
skb->protocol = eth_type_trans(skb, dev);  /* 設 pkt_type、拉掉 eth header */
/* AP 模式：如果 DA 是同 BSS 的 STA 且沒開 ap_isolate → intra-BSS 轉發，直接送回 TX path */
/* multicast 則同時上報並轉發 */
napi_gro_receive(napi, skb);   /* 或 netif_receive_skb / netif_receive_skb_list */

接著進入 __netif_receive_skb_core。如果介面掛在 bridge 上，會走 br_handle_frame (rx_handler)；否則依 skb->protocol 分派到 ip_rcv、ipv6_rcv 等。checksum 方面，如果 HW 有做 RX checksum offload，driver 要設定 skb->ip_summed = CHECKSUM_UNNECESSARY。

Debug 時常見的坑

  • HW 已經切好 MSDU，但沒有設 ALLOW_SAME_PN，結果第二個以後的 subframe 都被當成 replay 丟掉。症狀是吞吐量掉一半，rx_dropped 或 replay counter 持續增加。
  • reorder buffer 存的是 MSDU 而不是 MPDU，導致 BA window 的計算錯亂。
  • padding 沒有處理「最後一個 subframe 不補」，造成最後一個封包長度錯 1~3 bytes，或被判定為長度錯誤而整包丟棄。
  • Length 欄位當成 little-endian 處理。
  • MLO 下 A1/A2 是 link address，查 STA 時要先轉成 MLD address。subframe 內的 DA/SA 本來就是 MLD address，不需要轉換。
