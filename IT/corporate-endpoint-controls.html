公司電腦上的管控軟體盤點

以一台企業「管控型」Windows 筆電為例，從使用者權限（非管理員、透過 WSL）能看到的程序、服務、登錄檔與事件日誌，盤點 IT 疊了哪幾層管控、各自管得到什麼。重點拆解 BeyondTrust Privilege Management 與 TrustView 兩套。內容已去識別化：公司名稱、內網位址、帳號與政策代號一律省略。

1管控疊層總覽

這台電腦同時是 AD 網域成員、Azure AD 混合加入，並註冊了 Intune MDM。管控工具大致疊成七層：

權限控管BeyondTrust PM：能不能裝、能不能用 admin 執行 · 每次程序啟動都會經過
EDR（雙套）CrowdStrike Falcon ＋ Microsoft Defender for Endpoint · 程序、命令列、檔案、網路全記錄
DLP / DRMMicrosoft Purview Endpoint DLP ＋ TrustView · 文件能不能複製、截圖、列印、帶走
行為監控OCular Agent（TEC Solutions）＋ Omnissa Workspace ONE DEX · 使用活動、App 使用、效能
派送與遠端SCCM（含遠端控制）＋ Intune · 推送/移除軟體、軟體盤點、看你的桌面

3BeyondTrust PM 深入

定位：讓使用者平常以一般權限工作，需要管理員權限時由政策決定給不給。它管的是「權限」，不是資料。

運作方式

  • 核心驅動 PGDriver.sys ＋ 注入各程序的 PGHook.dll：每個 Windows 程序啟動前先比對政策，結果三選一：一般權限執行、加 admin token、封鎖。
  • 政策由公司的 BeyondInsight 伺服器下發，快取成 XML 在 C:\ProgramData\Avecto\Privilege Guard\BeyondInsight Cache\，一般使用者無讀取權限。
  • DefendpointBeyondInsightAdapter 負責把事件回傳伺服器。

每筆提權事件記錄什麼

Windows「應用程式」日誌，Event ID 100（本機用事件檢視器就看得到）。欄位包括：

欄位說明
File Name / Parent Process被提權的執行檔與它的父程序
User / Host網域帳號、主機名稱、SID
Workstyle / Application Group命中的政策規則
Token拿到的權限，例如 Add Full Admin (Required for Installers)
UAC Triggered、Product Code是否觸發 UAC、MSI 產品碼與版本

實際觀察到的事件都命中同一條規則：從「設定 > 應用程式」解除安裝時自動給完整 admin。解除安裝程式衍生出的子程序（taskkill、regsvr32、清理用 .bat）也會逐筆記錄，所以一次移除常會留下十幾筆。

4TrustView 深入

定位：台灣廠商的文件安全套件，以 DRM 為核心，加上 DLP 與受保護工作區（VDP）。它管的是「資料」。

  • 伺服器在公司內網（HTTPS 自訂埠）；本機有離線授權檔，離線時也照政策執行。
  • 使用者層登錄檔列出了已載入的外掛清單，可據此推斷啟用了哪些功能：

6對使用者的實際意義

HTTPS 內容

從 WSL 連 google.com，憑證簽發者是 Google Trust Services，不是公司 CA；系統也沒設 proxy。就這一個網站而言沒有被解密。但機器上已裝了 TecSign-Root 這類非公開根憑證，代表具備攔截 HTTPS 的能力；只測一個網域不能保證其他網域也沒有。

連線紀錄

連到哪個 IP、哪個網域（SNI），CrowdStrike、Defender NDR 與 TrustView 的 WFP 驅動都看得到。WSL 的流量經 Windows NAT 出去，同樣會被記錄。

WSL 內部

EDR 一定看得到 wsl.exe、vmmemWSL 在跑，也看得到網路連線。Linux 內部指令目前看不到：Defender 的 WSL plug-in 未安裝；CrowdStrike 雖隨附 WSL 外掛 DLL，但未註冊進 WSL（詳見 Falcon 那篇），IT 隨時可從後台啟用。從 Windows 端存取 \\wsl$ 的檔案操作會被記錄。

軟體清單

SCCM 與 Workspace ONE 會盤點所有已安裝軟體，非公司用途的軟體一覽無遺。封包工具（Wireshark、Npcap）、遠端桌面主機、FTP 伺服器這類軟體，在 EDR 上通常特別醒目。

磁碟內容（BitLocker／MBAM）

MBAMAgent 只做兩件事：把 BitLocker 復原金鑰上傳到 IT 的資料庫，以及回報加密合規狀態（是否加密、演算法、TPM）。它不掃描、也不上傳檔案內容。但這不代表 IT 讀不到你的磁碟：

  • 離線：BitLocker 防的是「筆電被偷、硬碟被拆去別台讀」。復原金鑰在 IT 手上，只要拿到實體硬碟（交還、送修、離職回收、鑑識調查）就能解密讀取全部內容。對 IT 而言它不是屏障，只擋外人。
  • 開機中：登入後磁碟已透明解鎖，任何 SYSTEM 權限的程式不需要金鑰就能讀檔。真正碰得到內容的是其他代理：CrowdStrike 與 MDE 的 live response 可遠端取回檔案、Purview／TrustView 會檢查文件內容、SCCM 可看桌面。實際啟用與否看伺服器端政策。
  • WSL：整個 Linux 檔案系統存成 C: 槽上的一個 ext4.vhdx，受同一把 BitLocker、同一份金鑰託管；對 IT 來說只是一個可掛載讀取的檔案。EDR 會不會掃描 vhdx 內部並未驗證，但「讀不讀得到」只看權限，與加密無關。

畫面

TrustView 有防截圖與浮水印；SCCM 可遠端看桌面；行為監控代理可能也會截圖。實際有沒有開，取決於伺服器端政策。

原則：公司電腦上的一切都假設 IT 看得到。被擋時記下時間與訊息找 IT 申請例外，不要改名、換路徑或嘗試停用代理程式；繞過行為本身就是 EDR 的告警條件。

7自己盤點的指令

從 WSL 呼叫時用完整路徑，並先 cd /mnt/c。以下都不需管理員權限。

# 1. 執行中程序與路徑
Get-Process | Select Name, Path -Unique | Sort Name

# 2. 非 svchost 的執行中服務（看廠商路徑）
Get-CimInstance Win32_Service | ? State -eq 'Running' |
  Select Name, DisplayName, PathName | Sort PathName

# 3. 網域 / Azure AD / MDM 加入狀態
dsregcmd /status | Select-String 'AzureAdJoined|DomainJoined|MdmUrl'

# 4. 非公開根憑證（TLS 攔截能力的指標）
certutil -store Root | Select-String 'Issuer'

# 5. 某個執行檔是哪家的
(Get-Item C:\Windows\System32\xxx.exe).VersionInfo |
  Select CompanyName, FileDescription, ProductName

# 6. BeyondTrust 提權紀錄
Get-WinEvent -LogName Application |
  ? { $_.ProviderName -match 'Avecto|Defendpoint' -and $_.Id -eq 100 }

# 7. TrustView 已載入外掛清單
Get-ChildItem HKCU:\SOFTWARE\TrustView\Settings -Recurse
# 8. 從 WSL 檢查 HTTPS 是否被重新簽發
echo | openssl s_client -connect www.google.com:443 \
  -servername www.google.com 2>/dev/null | grep issuer=

8這份盤點的限制

  • 以非管理員權限觀察；兩套主要軟體的政策檔都加密或鎖權限，功能是從模組名稱、登錄檔與事件日誌推斷的。
  • 「具備某能力」不等於「已啟用」。是否截圖、是否記鍵盤、是否稽核所有程序，都在伺服器端政策裡。
  • HTTPS 只測了一個網域。
  • 實際規範以公司 IT 的使用政策為準。
重點整理：這台電腦有權限（BeyondTrust）、雙 EDR（CrowdStrike ＋ MDE）、雙 DLP（Purview ＋ TrustView）、行為監控（OCular、Workspace ONE）、軟體派送與遠端控制（SCCM、Intune）、磁碟加密（MBAM）共六大類管控。BeyondTrust 決定你能執行什麼並記下每次提權；TrustView 決定公司文件能怎麼被使用，包含防截圖、浮水印、剪貼簿與列印管控。
