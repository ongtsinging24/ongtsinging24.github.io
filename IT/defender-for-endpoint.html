Microsoft Defender for Endpoint

公司電腦上那個叫「Windows Defender Advanced Threat Protection Service」的服務在做什麼：它和防毒軟體的差別、本機跑了哪些行程、IT 從後台看得到什麼，以及它為什麼每次關機都要多等十幾秒。

1它是什麼、名稱怎麼變的

MDE 是 Microsoft 賣給企業的端點資安平台。端點指的是員工的筆電、桌機和伺服器。它的核心是 EDR：在每台電腦上持續記錄行為，送到雲端分析，讓公司的資安團隊能偵測攻擊、調查經過，並遠端處置。

Windows 10／11 已經內建它的感測器，所以不用另外裝軟體。公司只要執行「上線」（onboarding）把電腦綁定到自己的租戶，感測器就會啟動。

2016　Windows Defender ATP
隨 Windows 10 周年更新（1607）推出，感測器內建在作業系統
2019　Microsoft Defender ATP
開始支援 macOS，名稱拿掉 Windows
2020　Microsoft Defender for Endpoint
改成現名；後來再支援 Linux、iOS、Android
現在　Microsoft Defender XDR 的一部分
和 Defender for Office 365、for Identity、for Cloud Apps 共用同一個後台（Microsoft Defender portal）

產品已經改名，但 Windows 裡的服務顯示名稱沒有跟著改，所以事件記錄裡仍然寫著 Windows Defender Advanced Threat Protection Service。

2跟防毒有什麼不同

防毒問的是「這個檔案是不是惡意的」；EDR 問的是「這台電腦剛剛發生了什麼事，前後連起來像不像攻擊」。很多攻擊根本不放惡意檔：直接用系統內建的 PowerShell、偷登入帳密、橫向移動到別台。只看檔案的防毒抓不到這種攻擊，EDR 從行為序列才看得出來。

防毒（AV）EDR（MDE 的核心）
看什麼檔案內容、特徵碼、行為啟發行程、命令列、網路連線、登錄檔、登入事件的時間序列
在哪裡判斷主要在本機本機感測器收集，雲端關聯分析
處理結果隔離或刪除檔案產生告警與事件（incident），把整條攻擊鏈畫出來
事後能做什麼幾乎不能回頭查可回查數十天到半年的記錄、遠端隔離電腦、開遠端 shell
誰在看多半沒人看，自動處理公司 SOC 或外包的資安廠商

MDE 這個產品同時包含兩者：Microsoft Defender Antivirus 負責防毒，Sense 感測器負責 EDR。兩者可以分開設定，第 6 節會講。

這些行程大多受防篡改保護（Tamper Protection）：即使有本機管理員權限，也無法停掉服務、改登錄檔或用 PowerShell 關閉防護。這是故意的設計，因為攻擊者拿到管理員權限後，第一件事通常就是關閉資安軟體。

4功能模組

授權分 Plan 1 和 Plan 2（中小企業另有 Defender for Business）。EDR、自動調查、進階搜捕屬於 Plan 2。下表列出主要模組；公司實際開了哪些，看授權和 IT 的設定。

模組做什麼使用者會感受到的
ASR 規則擋掉常被濫用的行為，例如 Office 開子行程、從 LSASS 讀帳密、執行來路不明的混淆腳本某些巨集或腳本突然跑不動，跳出「已被組織封鎖」
新世代防護Defender AV：即時掃描、雲端判斷、行為監控下載檔被隔離、大量讀寫時磁碟變慢
Network Protection／網頁內容過濾依信譽封鎖惡意或被禁止類別的網域，連瀏覽器以外的程式也擋某些網站連不上，或 CLI 工具連線失敗
Device Control控管 USB 隨身碟、印表機等週邊隨身碟只能讀、不能寫
EDR行為記錄、告警、攻擊鏈還原平常感覺不到
AIR告警觸發後自動調查並修復（刪檔、停行程）某支程式被自動處理，事後收到 IT 通知
Live ResponseSOC 對這台電腦開遠端 shell：列行程、收檔案、跑腳本平常感覺不到；調查期間可能被要求保持開機
裝置隔離切斷這台電腦所有網路，只保留和 MDE 雲端的連線突然完全斷網，但 IT 仍連得到這台電腦
TVM軟體盤點、弱點與設定評分IT 要求你更新或移除某個舊版軟體
Advanced Hunting用 KQL 查詢原始事件表平常感覺不到

5它收集什麼、IT 看得到什麼

這一節對使用者最實際。MDE 是給組織用的監控工具，資料屬於公司的租戶，有權限的 IT／資安人員都查得到。

類別看得到嗎說明
啟動了哪些程式看得到行程名稱、路徑、雜湊值、父子行程關係、啟動帳號
完整命令列看得到包含所有參數。直接寫在參數裡的 token、密碼都會被記下來
網路連線看得到哪支程式連到哪個 IP、哪個 port、哪個網域
檔案建立／修改看得到檔名與路徑、雜湊值；可疑檔可能被上傳做分析
登錄檔、排程任務、服務看得到特別是常被拿來做持久化的位置
登入事件看得到誰、何時、從哪裡、用什麼方式登入
檔案內容視情況不會全部上傳；可疑檔案、或 SOC 用 live response 主動收集時才會拿到
螢幕畫面、鍵盤輸入不收MDE 不是側錄軟體；公司若另外裝 DLP 或監控軟體則另當別論
HTTPS 網頁內容一般不收看得到連去哪個網域，看不到加密後的內容

資料保存期依授權與設定而定，常見設定是保留 180 天；Advanced Hunting 能直接查的大約是最近 30 天。

命令列記錄有多完整

一支程式啟動時收到的整串參數，會原文、一字不漏地記進後台的 ProcessCommandLine 欄位，旁邊還有時間、帳號、父行程與執行檔雜湊值。例如：

curl.exe -H "Authorization: Bearer sk-abc123..." https://api.example.com/v1/orders?acct=U1234567

這一整行連同 token 和帳號，會在保存期內一直查得到。要注意的是，記錄的單位是「啟動程式」，不是「你打的每一個字」：

行為會被記下嗎
在 cmd／PowerShell 啟動外部程式（curl.exe、git.exe、python.exe…）會，帶完整參數
PowerShell 內建指令與腳本內容（Get-Item、$x=...）大多會
用參數開網址：chrome.exe "https://...?token=xxx"會，網址就是參數
在瀏覽器網址列手打網址只看得到網域，看不到完整網址
環境變數的值不會，程式啟動事件不帶環境變數
設定檔內容一般不會（可疑檔被上傳、或 SOC 主動收集時例外）
WSL2 裡的 bash 指令（未裝 WSL plug-in）大致看不到
從 WSL 呼叫 powershell.exe、cmd.exe看得到，那是 Windows 端的程式

PowerShell 內建指令會被記錄，原因有兩個：MDE 有專門記錄 PowerShell 命令的事件類型；Windows 本身也有「可疑腳本區塊自動記錄」，即使公司沒開全量記錄政策，只要腳本內容碰到資安相關的字眼（例如查 Defender 狀態、讀安全政策登錄檔），就會在本機 Microsoft-Windows-PowerShell/Operational 留下 4104 警告事件，內容是腳本原文。第 8 節的自查指令跑下去，本身就會被記一筆。這不是壞事，但在 SOC 眼裡，這看起來就是「有人在列舉這台電腦的資安軟體」。被問到時照實說明用途即可。

可以自己看本機記了什麼：

Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PowerShell/Operational'; Id=4104; StartTime=(Get-Date).AddHours(-1)} |
  Select TimeCreated, LevelDisplayName, @{n='text';e={$_.Message.Substring(0,[Math]::Min(160,$_.Message.Length))}}

這算不算隱私問題

算，只是性質是「公司設備由公司監控」，不是被入侵。

  • 政策面：公司電腦的監控通常寫在 IT 使用規範／資安政策裡，入職時就簽過。雇主在事先告知、目的合理的前提下監控公司設備，一般是被允許的；細節以公司政策與當地法規為準。
  • 誰會看：後台權限分級，查詢本身也有稽核記錄。平常以自動分析為主，有告警或調查時才會有人看。但一旦開始調查，這台電腦數個月內的命令列都拉得出來。
  • 不只一家：如果公司另有第三方 EDR（第 6 節），它通常也記錄行程與命令列，要假設兩家都看得到。
實務建議：
  • 別把 API key、密碼寫在命令列參數裡（例如 curl -H "Authorization: Bearer xxx"、gh auth login --with-token xxx），也別寫死在 PowerShell 腳本裡；改用環境變數、設定檔或 git credential helper。命令列和腳本內容都會原文進入記錄。
  • 從 WSL 呼叫 powershell.exe -Command '...' 時，整串字串都會被 Windows 端記下，別把機密塞進去。
  • 公司電腦上做的事，預設都在記錄範圍內。私人帳號、私人資料放在私人裝置上。
  • WSL 的情況比較特殊。沒有安裝「MDE plug-in for WSL」時，EDR 只看得到 WSL 的外殼（wsl.exe、vmmem），看不太到 Linux VM 裡面跑了什麼行程。但 /mnt/c 底下的檔案就在 Windows 檔案系統上，照常會被掃描。公司可能隨時加裝這個 plug-in，不要把「看不到」當成常態。

6和第三方防毒並存

很多公司的主力防毒／EDR 是別家（例如 CrowdStrike、SentinelOne、Trend Micro），但同時也開著 MDE。兩套都做即時掃描會互搶檔案、拖慢系統，所以 Defender AV 會自動退到被動模式，即時掃描交給主力那家；MDE 的 EDR 感測器則繼續收資料。

PowerShell 的 Get-MpComputerStatus 用 AMRunningMode 欄位顯示目前的模式：

AMRunningMode意思
NormalDefender AV 是主力防毒，即時掃描開著
Passive另一套防毒是主力；Defender AV 不做即時掃描，但仍會更新特徵碼並回報
EDR Block Mode被動模式，外加「EDR in block mode」：主力防毒漏掉、但 MDE 的 EDR 判定為惡意的東西，Defender 仍會直接封鎖或修復
SxS Passive Mode並存（side-by-side）被動模式，只做有限的定期掃描

這也是為什麼同一台電腦上可能同時看到兩套資安軟體在跑。這是公司刻意的雙層配置，不是重複安裝。

7對關機與效能的影響

關機時的 7043 事件

Windows 關機時，服務控制管理員（SCM）會先送一個 preshutdown 通知給有登記的服務，意思是「要關機了，先收尾」。Sense 有登記這個通知，合理的推測是它在關機前把還在本機的事件記錄落地或送出，避免關機前那段時間的記錄遺失。

如果它在時限內沒收尾完，SCM 就在 System 記錄留下一筆：

Service Control Manager  7043
The Windows Defender Advanced Threat Protection Service service did not
shut down properly after receiving a preshutdown control.

然後照樣繼續關機。所以 7043 本身不是錯誤，只是表示「它被等到時限、沒有乾淨地收尾」。實務上每次重啟會固定多花十幾到二十秒。

怎麼判斷正不正常：這段時間通常每次差不多。如果某天突然拖到一分鐘以上，比較可能是連不到 MDE 雲端（例如 VPN 斷了、proxy 有問題），或磁碟本身很忙。可以先比對 7043 前後的時間戳，或到事件檢視器看 Microsoft-Windows-SENSE/Operational 有沒有連線錯誤。

平常的效能

  • 吃資源的通常是 MsMpEng.exe（AV 掃描），不是 MsSense.exe。EDR 感測器只記錄事件，負擔比較輕。
  • 建置、解壓縮、git checkout、npm install 這類一次動到大量小檔的工作最容易被即時掃描拖慢。解法是請 IT 設排除路徑，或在 Windows 11 使用 Dev Drive。自己設排除通常會被防篡改保護擋下，也不該繞過。
  • WSL2 的 Linux 檔案系統（ext4 虛擬磁碟）不會被 Defender AV 逐檔即時掃描；跨到 /mnt/c 的讀寫才會。這是 WSL 裡開發時「放在 Linux 端比放在 C: 快」的原因之一。

8自己查狀態的指令

以下都可以用一般使用者權限在 PowerShell 執行。中文 Windows 建議先設定輸出編碼，避免亂碼。

[Console]::OutputEncoding = [Text.Encoding]::UTF8

# 1. 服務在不在跑
Get-Service Sense, WinDefend, MdCoreSvc | Select Name, Status, StartType

# 2. 有沒有上線到公司租戶（1 = 已上線）
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows Advanced Threat Protection\Status' |
  Select OnboardingState, LastConnected
#    LastConnected 是 FILETIME（UTC）：
[DateTime]::FromFileTimeUtc((Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows Advanced Threat Protection\Status').LastConnected)

# 3. 防毒模式與防篡改
Get-MpComputerStatus | Select AMRunningMode, AMProductVersion, RealTimeProtectionEnabled,
  IsTamperProtected, AntivirusSignatureLastUpdated

# 4. 系統登記了哪些防毒（看得出主力是不是別家）
Get-CimInstance -Namespace root/SecurityCenter2 -ClassName AntivirusProduct | Select displayName

# 5. 近 60 天關機時 preshutdown 逾時的記錄
Get-WinEvent -FilterHashtable @{LogName='System'; Id=7043; StartTime=(Get-Date).AddDays(-60)} |
  Select TimeCreated, Message

# 6. 感測器自己的記錄（連線錯誤看這裡）
Get-WinEvent -LogName 'Microsoft-Windows-SENSE/Operational' -MaxEvents 30 |
  Select TimeCreated, Id, LevelDisplayName, Message

從 WSL 呼叫時，用完整路徑 /mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe，並先 cd /mnt/c，避免工作目錄是 \\wsl$ 路徑時出錯。

9遇到問題怎麼辦

狀況建議
程式或腳本被擋，跳出「已被組織封鎖」記下時間、程式路徑和通知內容，找 IT 申請例外。不要改名或換路徑重跑，換個方式繞過本身就是 EDR 會告警的行為
突然整台斷網，只剩某些服務能連可能被裝置隔離了，代表 SOC 正在調查。直接聯絡 IT，不要自己重灌或拔網卡
建置、git 操作明顯變慢確認是 MsMpEng.exe 在吃資源後，請 IT 評估排除路徑，或把工作目錄搬到 Dev Drive／WSL 內部
重啟比平常慢很多用第 8 節的指令 5 看 7043 的時間戳，先排除其他服務（例如雲端硬碟的檔案系統驅動）造成的延遲，再判斷是不是 MDE
想關掉它不行，也不應該。公司電腦的資安軟體屬於公司的合規要求，防篡改保護也會擋下
重點整理：MDE 是公司放在你電腦上的資安監控，會記錄程式、命令列和網路連線並送到公司的資安後台。它不側錄畫面或鍵盤，但命令列看得一清二楚。關機時多等的十幾秒是它在收尾，屬於正常成本；要處理的是突然變得很久的情況。
