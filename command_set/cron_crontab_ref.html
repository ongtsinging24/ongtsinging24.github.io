00術語與縮寫

縮寫 / 術語說明
daemon常駐背景服務程序
cron源自希臘文 chronos(時間),排程用 daemon
crontabcron table:排程表本身,也是編輯排程表的指令
DOM / DOWDay of Month / Day of Week,日期欄與星期欄
$PATHshell 搜尋可執行檔的路徑清單
stdin / stdout / stderr標準輸入 / 標準輸出 / 標準錯誤輸出
MTAMail Transfer Agent,本機寄信程式;cron 預設用它寄出工作輸出
flockfile lock,以檔案鎖防止同一工作重疊執行
run-parts依序執行某目錄內所有可執行檔的工具(cron.daily 等使用)
anacron補跑「關機期間錯過」的每日/每週工作的輔助程式
systemd timersystemd 內建排程機制,cron 的現代替代方案

01兩者的關係

croncrontab
角色背景 daemon(執行者)使用者端工具(編輯者)
誰啟動開機由 init / systemd 啟動使用者手動執行
位置/usr/sbin/cron(RHEL 系為 crond)/usr/bin/crontab
工作每分鐘醒來,檢查並執行到期工作檢視 / 編輯 / 刪除個人排程表

個人排程表實際存在 /var/spool/cron/crontabs/<user>(cronie 為 /var/spool/cron/<user>)。不要直接編輯此檔,一律透過 crontab 指令,它會做語法檢查並通知 daemon 重新載入。

⚠ 陷阱:一般使用者不需要、也不應手動執行 cron。而直接打 crontab 不帶參數時,部分實作(如 cronie)會「從 stdin 讀入新排程表」並停住等輸入 — 此時按 Ctrl-C 離開,不要按 Ctrl-D,否則可能以空內容覆蓋整份排程。

02確認 cron daemon 在跑

systemctl status cron        # Debian/Ubuntu
systemctl status crond       # RHEL/Fedora(cronie)
pgrep -a cron                # 不依賴 systemd 的通用作法
WSL2:預設不會自動啟動 cron。手動啟動 sudo service cron start,或在 /etc/wsl.conf 加入 [boot] systemd=true 後以 sudo systemctl enable --now cron 讓它常駐。

03crontab 指令

指令作用
crontab -l列出目前排程
crontab -e以 $EDITOR 編輯,存檔即生效(Ubuntu 首次會詢問編輯器,可用 select-editor 重選)
crontab -r刪除整份排程,不確認 ⚠
crontab -i -r刪除前先詢問
crontab file.txt以檔案內容整份取代排程
sudo crontab -u alice -l檢視 / 編輯其他使用者的排程
⛔ 注意:-r 與 -e 在鍵盤上相鄰,手滑一次排程全滅。養成備份習慣:crontab -l > ~/crontab.bak,或把排程納入 git 管理,用 crontab my.cron 部署。

04排程格式

┌──────── 分     (0-59)
│ ┌────── 時     (0-23)
│ │ ┌──── 日 DOM (1-31)
│ │ │ ┌── 月     (1-12 或 jan-dec)
│ │ │ │ ┌ 星期 DOW (0-7,0 與 7 皆為週日;或 sun-sat)
│ │ │ │ │
* * * * *  要執行的命令

運算子

符號意義例
*任意值* * * * * 每分鐘
,列舉0 9,21 * * *
-範圍1-5 週一到週五
/間隔*/15 每 15 單位

常用範例

排程意義
30 8 * * 1-5平日 08:30
*/15 * * * *每 15 分鐘
0 9,21 * * *每天 09:00 與 21:00
0 22 * * 1-5平日 22:00
0 3 1 * *每月 1 號 03:00

特殊字串

字串等同
@rebootcron daemon 啟動時執行一次
@hourly0 * * * *
@daily / @midnight0 0 * * *
@weekly0 0 * * 0
@monthly0 0 1 * *
⚠ 語法陷阱 1:DOM 與 DOW 同時指定時是「或」。0 0 1 * 1 是「每月 1 號或每週一」,不是「剛好是週一的 1 號」。
⚠ 語法陷阱 2:% 在 crontab 中代表換行(其後內容會變成 stdin)。date +%F 必須寫成 date +\%F。

05執行環境陷阱(最常見的失敗原因)

互動式 shell 能跑、放進 cron 就失敗,九成是以下原因:

#cron 的實際行為後果對策
1$PATH 僅 /usr/bin:/bin,不讀 .bashrcconda / venv 未啟用、自訂工具找不到一律寫絕對路徑,或在 crontab 開頭設 PATH=
2工作目錄是 $HOME腳本內相對路徑失效先 cd /abs/path &&
3shell 是 /bin/sh(Debian 上是 dash)bash 語法([[ ]]、source)報錯開頭加 SHELL=/bin/bash
4輸出經 MTA 寄成本機郵件未設郵件時輸出直接消失重導 >> log 2>&1;或設 MAILTO="" 關閉寄信
5依系統時區觸發伺服器若為 UTC,時間差 8 小時timedatectl 確認;cronie 可用 CRON_TZ=
conda 環境不必 activate:直接呼叫該環境的 Python 絕對路徑(which python 查得),即會使用該環境的套件。

06實戰範本

以 ~/ongtradingsys/log_gen_by_roma/video_digest 為例。先在已啟用環境的 shell 取得 Python 絕對路徑:

$ which python
/home/ojy/miniconda3/envs/python3/bin/python   # 以實際輸出為準

再 crontab -e 加入:

SHELL=/bin/bash
MAILTO=""

# 平日 07:30 產生 video digest
30 7 * * 1-5  cd /home/ojy/ongtradingsys/log_gen_by_roma/video_digest && flock -n /tmp/vdigest.lock /home/ojy/miniconda3/envs/python3/bin/python digest.py >> cron.log 2>&1
片段目的
cd ... &&修正工作目錄;cd 失敗就不往下執行
Python 絕對路徑免 conda activate,直接使用該環境
flock -n上一輪未結束則跳過本輪,防重疊執行
>> cron.log 2>&1stdout 與 stderr 都附加寫入 log
MAILTO=""不寄本機郵件
⚠命令要寫在同一行,crontab 不支援 \ 續行。命令太長時,改寫成 shell 腳本,crontab 只呼叫腳本。

07除錯

# 1. 有沒有被觸發?
grep CRON /var/log/syslog | tail
journalctl -u cron --since today          # systemd 環境

# 2. 在「cron 級別的精簡環境」重現
env -i HOME="$HOME" PATH=/usr/bin:/bin /bin/sh -c '你的命令'

# 3. 臨時改成每分鐘跑,觀察 log 後再改回
* * * * *  ... >> /tmp/cron_debug.log 2>&1
症狀可能原因
syslog 無 CRON 紀錄daemon 沒在跑(WSL2 常見)、時間 / 時區算錯
有觸發但沒結果PATH、工作目錄、未重導輸出
log 出現 command not found沒用絕對路徑
命令在 % 處被截斷未跳脫 %
/etc/cron.daily 腳本沒跑檔名含 .,或未 chmod +x

08系統層級排程

位置格式說明
crontab -e(個人)5 欄 + 命令以自己的身分執行
/etc/crontab5 欄 + 使用者 + 命令系統全域,需 root 編輯
/etc/cron.d/*同 /etc/crontab套件或部署工具放置個別排程
/etc/cron.{hourly,daily,weekly,monthly}/直接放可執行腳本由 run-parts 執行
# /etc/cron.d/backup 範例(多了 user 欄)
0 3 * * *  root  /usr/local/bin/backup.sh
⚠ run-parts 檔名規則:Debian 只執行檔名符合 [A-Za-z0-9_-] 的檔案 — backup.sh 會被靜默忽略,須改為 backup。可用 run-parts --test /etc/cron.daily 檢查。

權限控管:/etc/cron.allow 若存在,僅列出的使用者可用 crontab;否則 /etc/cron.deny 列出的使用者被禁止。

09替代方案:systemd timer

需要「關機錯過要補跑」、整合 journald log、資源限制、相依其他服務時,systemd timer 較合適。使用者層級範例:

# ~/.config/systemd/user/vdigest.service
[Unit]
Description=video digest

[Service]
Type=oneshot
WorkingDirectory=%h/ongtradingsys/log_gen_by_roma/video_digest
ExecStart=%h/miniconda3/envs/python3/bin/python digest.py

# ~/.config/systemd/user/vdigest.timer
[Timer]
OnCalendar=Mon..Fri 07:30
Persistent=true          # 錯過的排程在開機後補跑

[Install]
WantedBy=timers.target
systemctl --user daemon-reload
systemctl --user enable --now vdigest.timer
systemctl --user list-timers               # 檢視下次觸發時間
journalctl --user -u vdigest.service       # 檢視輸出
systemd-analyze calendar 'Mon..Fri 07:30'  # 驗證時間表達式
面向cronsystemd timer
設定一行搞定需 .service + .timer 兩個檔
錯過補跑否(需 anacron)Persistent=true
Log自行重導自動進 journald
防重疊需 flock內建(服務執行中不會重複啟動)
可攜性幾乎所有 Unix僅 systemd 系統
適用簡單、快速正式、需可觀測性

使用者層級 timer 預設只在使用者登入時運作;要登出後仍執行,需 sudo loginctl enable-linger $USER。

10速查與鐵律

crontab -l                      # 看
crontab -l > ~/crontab.bak      # 備份(改之前先做)
crontab -e                      # 改
crontab ~/crontab.bak           # 還原
grep CRON /var/log/syslog       # 查有沒有觸發

五條鐵律

  1. 改之前先備份,永遠不要用不帶 -i 的 crontab -r。
  2. 一律寫絕對路徑(直譯器、腳本、輸出檔),不依賴 $PATH 與工作目錄。
  3. 一律重導輸出 >> log 2>&1,否則失敗時毫無線索。
  4. % 要寫成 \%;DOM 與 DOW 同時指定是「或」。
  5. 可能跑很久的工作加 flock -n,避免重疊執行。
