Git 參考卡 — 多機同步卡住時：「工作區有改動」不等於「擋路」

兩台機器、多個 repo 都推同一個 remote。同步腳本報出「有未提交改動，而且落後遠端 N 個 commit」時，最直覺的反應是 stash 或全部 add -A。本卡記錄一次實際排解：先找出本機和遠端改到的檔案交集，再把交集裡的檔案分成三類各自處理。全程只用 merge，沒有任何檔案遺失。

git 2.x / bash 多 remote ／ 巢狀 repo dirty ≠ blocking merge=union scoped commit

00術語與縮寫

WT
working tree，工作區。磁碟上實際的檔案內容，包含還沒 commit 的改動。
dirty
工作區「髒」：有已修改（M）或尚未追蹤（??）的檔案。
ahead / behind
本機分支比遠端多幾個 commit／少幾個 commit。同步腳本常用 ↑N／↓N 表示。
diverged
分叉：ahead 和 behind 同時大於 0，只能靠 merge 或 rebase 收斂。
ff
fast-forward：本機沒有自己的新 commit，pull 只是把分支指標往前移。
scoped commit
只提交指定的路徑：git commit -- <paths>。index 裡其他已 staged 的內容不會被一起帶走。
merge=union
.gitattributes 的合併驅動：兩邊都新增的行全部保留，不產生衝突標記。適合只會往檔尾追加的索引檔。
交集
本機髒檔清單 ∩ 遠端帶進來的變更清單。只有交集裡的檔案會讓 pull 失敗。

01問題起點

同步腳本先 fetch 再顯示狀態，兩個 repo 呈現同一個型態：

./                 [master] →GHRemote  ✎ 2 改·5 新   ↓13 需 git pull
public_article     [main]   →GHRemote  ✎ 3 改·1 新   ↓4 需 git pull
摘要（6 repo）: 4 乾淨  2 未提交  2 需 pull

腳本預設的保護策略是「工作區髒就不自動 pull」，所以兩個 repo 都停住，等人來判斷。

為什麼不直接 pull

只要本機髒檔和遠端的變更碰到同一個檔案，git pull 就會中止，並顯示 Your local changes to the following files would be overwritten by merge。不同檔案則完全不受影響，git 會原樣保留它們。

02核心觀念：髒檔分三類

類型怎麼認處理
不在交集遠端沒有動到這個檔不用處理。pull 會保留它
交集・人寫的成果筆記、索引、手寫的卡片；只有本機有這份內容先 scoped commit 再 pull，讓 git 做三方合併
交集・機器產出daemon／排程產生的報表，兩台各跑一輪；看檔頭時間戳依「採最新那份」：先備份本機版，再 git checkout -- 丟棄，改用遠端版
（特例）設了 union 的索引.gitattributes 有 merge=union同第二類：先 commit，pull 後兩邊新增的行都會保留
反直覺的地方

未追蹤的檔案（??）通常不擋 pull。例外：遠端剛好新增了同一條路徑，這時 git 會報 untracked working tree files would be overwritten。所以未追蹤的檔案也要拿去和交集比對一次。

03流程總覽

gh_sync --no-auto -f （只 fetch，看狀態） │ ├─ ↓N 且 ✓乾淨 ──────────────▶ 直接 pull（ff） │ └─ ↓N 且 ✎髒 │ ▼ 算交集 = 本機髒檔 ∩ 遠端變更 │ ┌──────────┼─────────────────┐ ▼ ▼ ▼ 不在交集 交集・人寫的成果 交集・機器產出 (不動) scoped commit cp 備份 → checkout -- └──────────┴────────┬────────┘ ▼ pull --no-rebase（merge） ▼ 檢查衝突標記 = 0 → push ▼ 再跑一次 gh_sync 驗收

04逐步指令

Step 1：只看狀態，不自動同步

./gh_sync.sh --no-auto -f      # -f 先 fetch；--no-auto 不做任何寫入

Step 2：算交集

git diff --name-only HEAD GHRemote/master > $T/remote.txt   # 遠端會帶進來的檔
git status --porcelain | cut -c4- | sort  > $T/local.txt    # 本機髒檔（含 ??）
sort $T/remote.txt | comm -12 - $T/local.txt                 # 交集

巢狀 repo 要各自進去跑一次（父 repo 看不到它們的內容），而且分支名稱可能是 main 而不是 master。

Step 3：判斷交集裡每個檔案屬於哪一類

git diff <file>                          # 本機改了什麼
git diff HEAD GHRemote/master -- <file>   # 遠端改了什麼
git check-attr merge -- <file>           # 有沒有 union
git log --oneline --stat HEAD..GHRemote/master   # 遠端那幾個 commit 各動了什麼（含刪檔、改名）

Step 4a：人寫的成果 → scoped commit

git add -- <new_file> <index_file>                 # 新檔要先 add 才能 commit
git commit -m "..." -- <new_file> <index_file>     # 只提交這幾條路徑

Step 4b：機器產出 → 先備份再丟棄

cp <report.md> $BACKUP/local_<report>_<HHMM>.md
git checkout -- <report.md>

Step 5：合併、檢查、推送、驗收

git pull --no-rebase --no-edit GHRemote master
grep -c '^<<<<<<<' <union_file>                # 結果必須是 0
git push GHRemote HEAD:master
./gh_sync.sh --no-auto -f                           # 摘要不應再出現「需 pull」

06禁忌

不要做

git stash：在共用的工作區（多個 session 或 daemon 同時寫）會把別人還沒提交的工作一起收走，stash pop 時還可能衝突。

git add -A：把不屬於這次任務的檔案一起 commit，等於替別人做決定。

git reset --hard 或 -hp 強制對齊：本機未推送的 commit 和改動會被靜默丟掉。

rebase ＋ force-push：另一台機器已經基於舊歷史工作，改寫歷史會讓它下次同步時分叉。

一定要做

丟棄任何本機版本之前，先 cp 一份備份。pull 之後先 grep 衝突標記再 push。

07速查

# 1. 看狀態
./gh_sync.sh --no-auto -f
# 2. 交集
comm -12 <(git diff --name-only HEAD GHRemote/master | sort) \
         <(git status --porcelain | cut -c4- | sort)
# 3a. 人寫的 → scoped commit
git add -- A B && git commit -m "..." -- A B
# 3b. 機器產出 → 備份後丟棄
cp R $BACKUP/ && git checkout -- R
# 4. 合併 → 檢查 → 推
git pull --no-rebase --no-edit GHRemote master
git diff --name-only --diff-filter=U        # 未解衝突清單，應為空
grep -c '^<<<<<<<' <union_file>        # 應為 0
git push GHRemote HEAD:master
預防勝於排解

人寫的成果在收工時就先 commit。這樣下次會卡住的只剩機器產出，一律「備份後採遠端」，就不必再逐檔判斷。
