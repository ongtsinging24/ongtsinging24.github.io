roma_cli vdc 會觸發哪些動作、用到哪些工具

一行指令背後的完整呼叫鏈：CLI 進入點、shell 外殼的鎖與閘門、Python runner、字幕與 Whisper 兩條轉錄路線，以及 NVIDIA CUDA 函式庫怎麼被載入。

ojy@ong-home-pc:~/ongtradingsys$ roma_cli vdc

縮寫說明

video_digest 的英文博主版 / 中文博主版

抓片＋轉錄，產出逐字稿；本頁主題
Stage B
把逐字稿整理成文章（在 Claude Code 下 VD2A），不屬於 vdc

0呼叫鏈總覽

  1. romasys/roma_cli → _cmd_video_digest()指令表 "vdc" 對應這個函式；決定帶 --lang zh。不經 ROMA daemon / socket。
  2. src/video_digest/cron_stage_a.sh併發鎖、跑前跑後計數、產出閘、版本閘、故障告警。
  3. src/video_digest/run.sh設定 CUDA 函式庫路徑，用模組自己的 .venv 執行 runner。
  4. python -m video_digest.runner --all --max-n 1 --lang zh讀 creators.yaml，逐位博主列片、過濾、處理最新 1 支。
  5. process_video() → fetcher / transcriber / state抓 metadata → 去重 → 字幕或 Whisper 轉錄 → 落檔 → 記錄 state.json。

1進入點：roma_cli

  • vdc 帶 --lang zh（只跑中文博主）；vd 帶 --lang en。
  • 實際動作只有一行：subprocess.run(["bash", cron_stage_a.sh, "--lang", "zh"])。
  • 跑完只印提示：新逐字稿要手動同步，Stage B 要另外跑。不做 git push，也不發通知。
roma_cli vdc -h          # 印用法，不觸發 Stage A
roma_cli vdc             # 中文博主各抓最新 1 支 → 轉錄
roma_cli vd              # 英文博主版

2外殼：cron_stage_a.sh

步驟動作
併發鎖flock -n 鎖 /tmp/video_digest_stage_a.lock。cron（每天 16:30、08:00）或另一次手動觸發正在跑時，這次直接結束，避免兩份同時寫 state.json
跑前計數數今天目錄 log_gen_by_roma/video_digest/DD-MM-YYYY/ 下有幾份 *.transcript.md
執行run.sh --all --max-n 1 --lang zh，輸出用 tee 同時寫進暫存 log
跑後計數跑後份數減跑前份數，就是這次新增幾份
產出閘從 log 抓 [runner] SUMMARY 那一行；fail 加 list_fail 大於 0 才告警
版本閘log 裡出現 [fetcher] STALE-YTDLP 也告警
告警出口用系統 python3 呼叫 notifications.transport.emit_alert，寫到 console 和 risk_log；ROMA_VD_ALERT_TG=0 可關
告警只看「故障」，不看「有沒有落檔」。博主今天沒發片、或影片已處理過，都算健康；只有「列表拉不到」或「列到片但處理時拋例外」才算故障。只看落檔數會無法分辨「今天本來就該沒有」，變成狼來了。

3執行環境：run.sh

  • 在模組自帶的 .venv 裡找 pip 裝的 nvidia/cublas/lib 和 nvidia/cudnn/lib，加進 LD_LIBRARY_PATH。
  • 切到 romasys/src，以 .venv/bin/python -m video_digest.runner 執行。

4主流程：runner.py cli()

  1. fetcher.warn_if_ytdlp_stale() 檢查 yt-dlp 版本年齡，超過 90 天印警告。
  2. 讀 creators.yaml，只留 lang: zh 的博主（目前 11 位）。
  3. 每位博主：
    • 列片單：有 playlist_id 用 list_playlist_videos，否則用 list_recent_videos(channel_id)。兩者都是 yt-dlp 的 extract_flat，只抓清單、不下載。
    • 有 title_include 的博主：先多掃 scan_n 支，用標題 regex 過濾，再用 max_duration_min 剔掉整集直播。
    • 取最新 1 支，交給 process_video()。
  4. RunTally 統計並印出 SUMMARY creators/listed/ok/skip/fail/list_fail。

5單支影片：process_video()

  1. fetch_video_metadata：yt-dlp 讀單片完整資訊。
  2. 去重：state.is_processed(id) 為真就略過（記為 skip，屬正常）。
  3. 轉錄，依 transcribe_route 分兩條：
    • caption_first：download_caption 依語言優先序逐一試抓 VTT，每試一次間隔 1.5 秒避開 429；parse_vtt 去掉時間碼、<c> 標籤和滾動字幕的重複行。抓不到字幕就改走 Whisper。
    • whisper_only：download_audio（bestaudio，優先 m4a）→ transcriber.transcribe_audio。
  4. 寫出 {alias}_{title}.transcript.md。_dedup_base 防「同標題、不同影片」互相覆寫：撞名時檔名加 __{date}_{id}。
  5. --with-api-summary、--with-article-digest（呼叫 Claude API）vdc 預設都沒開，只產逐字稿。
  6. state.mark_processed()：先寫 .tmp 再 rename，原子寫入 state.json。
  7. 刪除暫存的音檔和 VTT；刪失敗會印警告（音檔數十 MB，累積會吃空間）。

7轉錄層細節：faster-whisper ＋ CTranslate2

第 6 節表格裡的兩列（語音轉文字、推論引擎），對應的程式碼是 src/video_digest/transcriber.py 的 _load_whisper()（載入模型）和 transcribe_audio()（實際轉錄）。

faster-whisper：ASR 本體

  • 是什麼：OpenAI Whisper 模型的另一套實作。權重相同，但推論不走 PyTorch，交給 CTranslate2 執行。官方宣稱速度約快 4 倍、記憶體也更少，準確度不變。
  • 選模型：依博主在 creators.yaml 的 spoken 欄位決定。
    • 中文、粵語用 large-v3：多語言最大模型，最準，但也最慢、最吃顯存。
    • 英文（vd）用 medium.en：英文專用，準確度接近 large，速度快很多。.en 變體只接受英語，所以程式會強制把 language 設成 "en"。
  • beam_size=5：每一步保留 5 條候選序列一起往下搜尋，不是每步只挑機率最高的那個字（greedy）。比較不容易聽錯，也比較少出現重複或亂生的句子，代價是比較慢。5 是 Whisper 官方預設值。
  • 開 VAD（vad_filter=True）：先用 Silero VAD 把沒有人聲的段落切掉（靜音、片頭音樂、廣告空檔）。有兩個好處：
    1. 不處理靜音，速度變快。
    2. 防止 Whisper 最常見的毛病：在靜音段「幻聽」，憑空生出「謝謝觀看」「字幕由…提供」，或一直重複同一句。

CTranslate2：推論引擎

  • 是什麼：OpenNMT 團隊寫的 C++ Transformer 推論引擎，faster-whisper 的運算核心都在這裡。
  • 選硬體：設定 device、compute_type 是 auto（預設）時：
    • ctranslate2.get_cuda_device_count() > 0 → cuda ＋ float16：半精度在 GPU 上快，顯存約減半，準確度幾乎無損。
    • 否則 → cpu ＋ int8：8-bit 量化，CPU 上快 2–3 倍，準確度只掉一點。
    • 偵測時如果 import ctranslate2 本身就拋例外，直接當成 cpu。
  • 退路：模型載入失敗（例如顯存不夠、CUDA 函式庫沒接上）時，改用 fallback_model（預設 medium）、固定 cpu ＋ int8。整條流程不會中斷，只是變慢、準確度略降。
