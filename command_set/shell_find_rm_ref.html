Shell 參考卡 — find / rm 批次刪檔的三種正確寫法

從一次真實的 paths must precede expression 錯誤出發,拆解檔名含空白與中文時,為什麼多數人習慣的寫法會壞掉,以及三種安全替代方案的逐字元解析。

bash / GNU coreutils findutils glob 展開 word splitting end-of-options

00術語與縮寫

glob
shell 的檔名展開樣式,如 *、?、[abc]。由 shell 執行,不是由命令本身執行。
word splitting
shell 把未加引號的字串依 $IFS(預設空格/tab/換行)切成多個參數的過程。
IFS
Internal Field Separator,shell 用來決定在哪裡切字的變數。
NUL
位元組 0x00。Unix 檔名中唯一絕對不可能出現的字元(另一個禁用字元是 /)。
ARG_MAX
核心對單次 exec() 命令列總長度的上限,Linux 典型值約 2 MB。超過會出現 Argument list too long。
end-of-options
POSIX 慣例的 -- 標記,表示其後的參數一律視為運算元(檔名),不再解析為選項。
getopt
C 標準函式庫解析命令列選項的常式,-- 的行為由它實作,因此絕大多數工具一致。
predicate
find 的「條件述語」,如 -name、-type、-maxdepth。

01問題起點:兩個連環失敗

實際情境:目錄中有數個中文長檔名的 *.transcript.md,檔名內含空白與全形字元。

# 檔名長這樣(注意其中的半形空白)
吳嘉隆_美國長債殖利率狂飆 衝破5%引發恐慌_拉高避險情緒成解方 川普欲藉戰爭降利率_....transcript.md

失敗 1 — find 的樣式沒加引號

$ find -name *.transcript.md
find: paths must precede expression: `吳嘉隆_美國長債殖利率狂飆 衝破5%引發恐慌_...md'
find: possible unquoted pattern after predicate `-name'?

原因:shell 先動手了。*.transcript.md 未加引號,shell 在啟動 find 之前就把它展開成當前目錄的所有符合檔名,於是 find 真正收到的是:

find -name 'A.transcript.md' 'B.transcript.md' 'C.transcript.md'
             └─ 樣式 ─┘      └─── find 認為這些是「路徑」,但路徑必須寫在條件前面 ───┘

find 的語法是 find [路徑...] [條件...],路徑必須排在條件之前。第二、三個檔名出現在 -name 之後,於是它抱怨「paths must precede expression」,並貼心猜到真正的病因是「unquoted pattern」。

失敗 2 — 用 $(...) 把結果餵給 rm

$ rm $(find -name *.transcript.md)   # 就算 find 那段修好了,這行還是會壞

命令替換 $(...) 的輸出會再經過一次 word splitting。檔名中的空白被當成分隔符,一個檔名被切成好幾段:

rm '吳嘉隆_美國長債殖利率狂飆' '衝破5%引發恐慌_拉高避險情緒成解方' '川普欲藉戰爭降利率_...md'
   └──── 三個都不存在 → 全部報錯;若碰巧存在同名檔案 → 刪錯東西 ────┘
核心觀念

$(find ...) 這個組合在檔名含空白時結構性不安全,不是「多加引號就好」——rm "$(find ...)" 反而會把整批檔名黏成一個參數,一樣錯。正解是根本不要讓檔名經過「文字 → 再分詞」這一輪,也就是下面三種方案。

02方案 A — find -exec ... +

find . -maxdepth 1 -name '*.transcript.md' -exec rm -- {} +
find . -maxdepth 1 -name '*.transcript.md' -exec rm -- {} + ① ② ③ ④ ⑤

① find

遞迴走訪檔案樹。語法骨架:find [起始路徑] [條件] [動作]。

② .

起始路徑,. 為目前目錄。可換成絕對路徑。

③ -maxdepth 1

限制深度:只看起始目錄這一層,不進子目錄。拿掉即為無限遞迴。

擺放位置

-maxdepth 屬於「全域選項」而非測試條件,習慣上必須放在 -name 等條件之前,否則 GNU find 會發出警告。

④ -name '*.transcript.md'

檔名比對條件,使用 glob 樣式,只比對檔名本身,不含路徑。

單引號是關鍵:加引號 → 樣式原封不動交給 find 自己比對;不加引號 → shell 先展開,重現第 01 節的失敗 1。

相關變體:-iname(忽略大小寫)、-path(比對完整路徑)、-type f(限定一般檔案,排除同名目錄,更保險)。

⑤ -exec rm -- {} +

片段意義
-exec開始定義要執行的命令
rm命令本體
--end-of-options 標記,其後一律視為檔名。防止 -foo.md 這類檔名被 rm 誤判成選項(詳見第 04 節)
{}佔位符,find 將找到的路徑代入此處
+-exec 的結束符,且指定批次模式

+ 與 \; 的差別

-exec rm -- {} +     # 湊成一次呼叫: rm -- a.md b.md c.md      → 快
-exec rm -- {} \;    # 每個各呼叫一次: rm -- a.md; rm -- b.md  → 慢

+ 的行為等同 xargs,會自動依 ARG_MAX 分批呼叫。用 \; 時分號必須跳脫,否則被 shell 吃掉當成命令分隔符。

為何安全

檔名從 find 直接以 exec() 的參數陣列傳給 rm,全程沒有轉成一整串文字再切開,所以空白、中文、換行、引號一律無害。

03方案 B — glob 直接交給 rm

rm -- *.transcript.md
rm -- *.transcript.md ① ② ③

① rm

remove。常用選項:-r(遞迴)、-f(強制、忽略不存在)、-i(逐一確認)、-v(顯示刪了什麼)。

② --

end-of-options 標記。理由見第 04 節。

③ *.transcript.md

這裡刻意不加引號,由 shell 負責展開。實際送給 rm 的是:

rm -- '吳嘉隆_美國長債殖利率狂飆...transcript.md' '吳嘉隆_吳嘉隆點出市場吊詭...transcript.md'

由 shell 展開的好處:每個檔名自成一個獨立參數,含空白、中文都不會被拆開。這與 $(find ...) 的「字串再分詞」是完全不同的機制,所以它安全。

引號規則速記

find -name 的樣式 要加引號(給 find 自己比對);rm 的 glob 不加引號(要讓 shell 展開)。兩者恰好相反,是最常搞混的一點。

無符合檔案時的陷阱

若沒有任何檔案符合,bash 預設把 *.transcript.md 原樣傳給 rm,於是報 No such file or directory。想讓它安靜展開成空,設 shopt -s nullglob。

限制:glob 只作用於當層。需要遞迴時,bash 可開 shopt -s globstar 後用 **/,但一般情境直接用方案 A 更乾淨。

04為什麼 -- 是必要的

因為 shell 展開後,rm 已經分不出「這個參數是使用者打的選項」還是「檔名剛好長得像選項」。

Unix 慣例是「- 開頭 = 選項」。命令拿到參數時只是逐一檢視字串開頭,它無從得知這串字是手打的、還是 glob 展開來的。

假設目錄裡有個檔案叫 -rf.transcript.md。glob 展開是依字母序排列的,- 開頭的檔名會排在最前面:

$ rm *.transcript.md
# shell 展開成 →
rm -rf.transcript.md 吳嘉隆_....md
   ↑ 被解析成選項 -r -f,不是檔名

結果:rm 開啟了遞迴強制模式,而你原本想刪的檔案變成它的操作目標。輕則行為不如預期,重則遞迴刪除目錄。

加上 -- 之後,rm 看到標記就停止解析選項,其後每一個參數一律視為檔名,-rf.transcript.md 被正確地當成一個要刪除的檔案:

rm -- -rf.transcript.md 吳嘉隆_....md

這個慣例是通用的

不只 rm。grep、cp、mv、chmod、git 等遵循 POSIX/GNU getopt 的工具都支援:

grep -- -v file.txt         # 搜尋字串 "-v",而不是套用 -v 選項
git checkout -- file.md     # 明確表示 file.md 是路徑,不是分支名
mv -- "$src" "$dst"
實務原則

只要參數來源不是你手動打死的字面值——glob 展開、變數 $file、xargs 餵進來、使用者輸入、{} 代入——就加 --。這也是方案 A 的 -exec rm -- {} + 同樣要寫 -- 的原因。

05方案 C — xargs -0

find . -maxdepth 1 -name '*.transcript.md' -print0 | xargs -0 rm --
find . -maxdepth 1 -name '*.transcript.md' -print0 | xargs -0 rm -- └─────────── 前半:找檔案,輸出清單 ───────────┘ ① └─ 後半:接清單,執行刪除 ─┘

前半的搜尋條件與方案 A 完全相同,差別只在結尾動作與後半段。

-print0

find 的輸出動作。預設的 -print 是「每個結果後接一個換行 \n」;-print0 改成「接一個 NUL 字元」。

① |

管線,把 find 的標準輸出接到 xargs 的標準輸入。

xargs

從標準輸入讀取一串字,組裝成命令列參數附加在指定命令後執行。與 -exec ... + 一樣會自動依 ARG_MAX 分批。

-0(等同 --null)

告訴 xargs:輸入是 NUL 分隔,不是預設的空白/換行。必須與 -print0 成對使用。

rm --

xargs 要執行的命令。它會把讀到的檔名接在 -- 之後,最終執行 rm -- 'a.md' 'b.md' ...。

為什麼非得 -print0 / -0 不可

xargs 預設的分隔符是空白(空格、tab、換行),而且還會自作主張解析引號與反斜線。用預設的 -print | xargs 處理含空白的中文檔名:

吳嘉隆_美國長債殖利率狂飆 衝破5%引發恐慌_拉高避險情緒成解方 川普欲藉戰爭降利率_...md
                      ↑ 空白                ↑ 空白
# xargs 把一個檔名拆成三個獨立參數 → 全部找不到,或刪錯東西

換成 NUL 分隔就沒這問題:NUL 是唯一不可能出現在檔名中的位元組,用它當分隔符 100% 無歧義。空白、換行、引號、$、中文、emoji 全部安全通過。

釐清

中文本身其實不是問題(UTF-8 編碼不含 NUL 位元組,xargs 會照樣傳遞)。真正的殺手是空白。這批檔名剛好兩者都有,所以容易誤以為是編碼問題。

xargs 的強項

# 平行跑 4 個程序
find . -name '*.md' -print0 | xargs -0 -P4 -I{} pandoc {} -o {}.pdf

其他常用旗標:-n 100(每批最多 100 個)、-I{}(把檔名放在命令中間而非結尾)、-t(執行前先印出實際命令)、-r(輸入為空時不執行)。

06三方案比較

面向A. -exec ... +B. rm -- *globC. -print0 | xargs -0
安全性天生安全,不經文字序列化安全(shell 展開即獨立參數)需正確配對 -print0/-0 才安全
遞迴子目錄可(移除 -maxdepth)否(需 globstar)可
相依程序僅 find僅 shell 內建多一個 xargs 程序
可攜性POSIX 標準,全平台POSIX 標準,全平台-print0/-0 為 GNU/BSD 擴充,非 POSIX
彈性命令固定在 find 語法內最低,只能單一命令最高:-P 平行、-n 分批、-I{} 換位置
無符合檔案時安靜不執行報 No such file(除非 nullglob)GNU xargs 安靜(建議加 -r)
適用時機日常首選只刪當層、手動確認過需平行化或複雜管線

07實測驗證紀錄

在 Linux / GNU coreutils 環境建立含空白、中文與 - 開頭的檔名實測,結果如下。

$ ls -a
-rf.transcript.md
a b c.transcript.md
keep.md
sub/
吳嘉隆_美國長債殖利率狂飆 衝破5%引發恐慌_川普欲藉戰爭降利率.transcript.md

1. 未加引號的 find(重現原始錯誤)

$ find . -maxdepth 1 -name *.transcript.md
find: paths must precede expression: `a b c.transcript.md'
find: possible unquoted pattern after predicate `-name'?

2. -- 的必要性 — 意外的現場實證

建立測試檔時,連 touch 自己都踩到同一個坑:

$ touch '-rf.transcript.md'
touch: failed to get attributes of 'f.transcript.md': No such file or directory
# touch 把 -rf 解析成選項 -r(參考檔案)+ -f,於是把剩下的 .transcript.md 當成 -r 的引數

$ touch -- '-rf.transcript.md'
# 成功

列出檔案時同樣中招:

$ ls *.transcript.md
ls: invalid option -- '.'
Try 'ls --help' for more information.
這不是理論

上面兩個錯誤是真的跑出來的。同樣的參數若交給 rm,-rf 就不是報錯而是靜默啟用遞迴強制刪除。這就是 -- 的價值。

3. 預設 -print | xargs vs -print0 | xargs -0

$ find . -maxdepth 1 -name '*.transcript.md' -print0 | xargs -0 -t echo RM
# -t 印出實際命令,三個檔名各自完整,含空白者被正確引用

4. 方案 A 實刪結果

$ find . -maxdepth 1 -name '*.transcript.md' -exec rm -- {} +
$ ls -a
keep.md   sub/
$ ls sub
deep.transcript.md      # ← -maxdepth 1 生效,子目錄未受影響

08速查與安全習慣

安全流程(建議固定照做)

# 步驟 1 — 先看清單,絕不跳過
find . -maxdepth 1 -name '*.transcript.md' -print

# 步驟 2 — 想看詳細資訊就換成 ls
find . -maxdepth 1 -name '*.transcript.md' -exec ls -la -- {} +

# 步驟 3 — 確認無誤才刪
find . -maxdepth 1 -name '*.transcript.md' -delete

GNU find 內建的 -delete 比 -exec rm 更直接(不啟動外部程序),但它是 GNU 擴充,且必須寫在條件之後——寫在前面會變成「先刪再篩」的災難。

引號規則一覽

位置加引號?理由
find -name '*.md'✅ 要加樣式要交給 find 自己比對
rm -- *.md❌ 不加要讓 shell 展開成獨立參數
rm -- "$file"✅ 要加變數展開必須加雙引號,否則會 word splitting
rm $(find ...)⛔ 不要用加不加都錯,改用方案 A/C

三條鐵律

  1. 刪之前先 -print。 中文長檔名打錯救不回來,Linux 沒有資源回收筒。
  2. 參數不是手打的就加 --。 glob、變數、xargs、{} 一律適用。
  3. 永遠不要用 $(find ...) 餵檔名。 這是結構性缺陷,不是引號問題。
一行版總結

日常刪檔用 find . -maxdepth 1 -name '*.ext' -print 確認,再把 -print 換成 -exec rm -- {} + 執行。
