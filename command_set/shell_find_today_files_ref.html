Shell 參考卡 — 列出目錄樹下「今天產生」的檔案

「今天產生」至少有三種定義：今天被改過、今天被建立、今天才進版控。三者對應不同的時間戳與工具。本卡記錄一次實測：原本建議的 -newerBt 在 GNU find 4.9.0 會直接報錯，而且檔案系統的 birth time 本身也不等於「第一次建立」。

bash / GNU findutils 4.9.0 coreutils stat 9.4 WSL2 ext4 mtime vs birth time atomic rename

00術語與縮寫

mtime
modification time，檔案內容最後一次被改寫的時間。ls -l 顯示的就是它。
ctime
change time，inode 中介資料（權限、擁有者、連結數）最後一次變更的時間。不是 creation time。
atime
access time，最後一次被讀取的時間。多數系統掛載時帶 relatime，不可靠。
birth / btime
inode 被建立的時間。ext4 有存這個欄位，Linux 要透過 statx() 系統呼叫才讀得到（kernel 4.11+）。
statx
較新的 stat 系統呼叫，可以讀到 birth time。舊工具如果沒改用它，就會說「這個系統沒有 birth time」。
atomic rename
安全寫檔手法：先寫暫存檔，再用 rename() 蓋掉原檔。結果是換了一個新 inode，所以 birth time 被重設成現在。
bfs
相容 find 語法的另一個實作（breadth-first search）。Claude Code 的 shell 會把 find 包成 bfs，行為可能和你終端機的 GNU find 不同。
-newerXY
find 的比較條件：檔案的 X 時間戳比參考值 Y 還新。m=mtime、B=birth、t=「參考值是一段時間字串」。

01理論框架：「今天產生」的三種定義

你真正想問的對應時間戳工具會誤收會漏掉
今天有哪些檔案被動過mtimefind -newermt今天被改寫的舊檔（log、daemon 產物）今天用 cp -p / tar 還原、保留舊 mtime 的檔案
今天有哪些檔案被建立birthstat -c %W、bfs -newerBt以 atomic rename 重寫的舊檔（編輯器、git、Python 寫檔）檔案系統不存 birth 的位置（部分 /mnt/c、網路掛載）
今天有哪些檔案第一次進 repogit 歷史git log --diff-filter=A ＋ git status今天被刪掉又加回來的檔案被 gitignore 的檔案；巢狀 repo 要逐一跑
核心觀念

「今天」的邊界是 $(date +%F)，也就是本機時區的 00:00。-newermt 用的是嚴格大於，所以剛好 00:00:00.000 寫入的檔案不會被列出（實務上可忽略）。

02實驗設計

在一個含多個巢狀 git repo、並有背景 daemon 持續寫 log 的實際工作目錄上（2026-09-29 晚間，本機時區 GMT+8），對同一棵樹跑四種方法，交叉比對結果：

  1. M：GNU find -newermt（mtime 口徑）
  2. B1：GNU find -newerBt（birth 口徑，原本建議的寫法）
  3. B2：bfs -newerBt，以及 GNU find 取 mtime 候選後再用 stat -c %W 過濾（birth 口徑的兩個替代）
  4. G：git log --since=midnight --diff-filter=A ＋ untracked（版控口徑）

對照組（驗證 birth 口徑是否真的等於「新建立」）：取 B2 認定「今天出生」的檔案，和「今天以前就已經出現在 git 歷史」的檔案取交集。交集不為零，就代表 birth time 被重設過。

03結果

方法結果判讀
M：GNU -newermt401 個檔案可用。其中 log 目錄與 daemon 產物佔大宗（前兩大子目錄合計 274 個）
B1：GNU -newerBt報錯，0 筆find: This system does not provide a way to find the birth time of a file. ＋ invalid predicate `-newerBt'
B2：bfs -newerBt381 個檔案可用，和 stat -c %W 過濾的結果完全一致（381 = 381）
B2：stat -c %W 為 0 的筆數0ext4 上每個檔案都有 birth，不是欄位缺值問題
對照組：birth=今天 ∩ 今天以前已在 git≥ 11 個只算了父 repo（下限）。例：MEMORY.md birth 22:06、mtime 22:19，但這個檔案早就存在
G：git 今天新增父 repo 94（＋untracked 3）；巢狀 repo 共 172（四個 repo 各為 158 / 7 / 5 / 2）語意最乾淨，但看不到 gitignore 的檔案。第一次盤點時只手動列了兩個巢狀 repo，漏掉 165 筆，後來改用 for r in */ 自動掃才補齊

為什麼 GNU find 說「系統不提供 birth time」

同一台機器上 stat（coreutils 9.4）讀得到 birth，bfs 也讀得到，所以不是 kernel 或檔案系統的問題。差別在這個版本的 GNU find 沒有透過 statx() 去取 birth time，因此判定系統不支援，並且把 -newerBt 當成非法條件。

$ command find . -type f -newerBt "$(date +%F)" -print
find: This system does not provide a way to find the birth time of a file.
find: invalid predicate `-newerBt'

$ stat -c '%w | %y' CLAUDE.md          # 同一台機器，stat 讀得到
2026-09-27 22:43:57.09 +0800 | 2026-09-27 22:43:57.09 +0800
訂正

本卡前一版的建議「只要新建的就用 find -newerBt，需要 findutils 4.9+」是錯的。4.9.0 在這台機器上實測直接報錯。當初這個建議會在 Claude Code 裡「看起來能跑」，是因為那個 shell 的 find 其實是 bfs（見下）。

同一個指令，兩個 shell 兩種結果

$ type -a find          # 在 Claude Code 的 Bash 工具裡
find is a function      # → 包成 bfs 執行
find is /usr/bin/find   # 你的終端機用的是這個（GNU）

在 AI 助手的 shell 驗證過的 find 指令，貼到自己的終端機不保證會有一樣的結果。要驗證 GNU 的行為，請用 command find 或 /usr/bin/find。

birth time 也不等於「第一次建立」

編輯器存檔、git checkout、許多 Python 寫檔函式都採用 atomic rename：先寫暫存檔，再 rename 蓋掉原檔。inode 換新了，birth 就跟著重設。所以一份九月初就存在的筆記，只要今天被存過一次，birth time 就會顯示今天。

04結論與速查

A. 今天被動過的（mtime，日常首選）

find . -path '*/.git' -prune -o -type f -newermt "$(date +%F)" -print | sort

A'. 附時間與大小，依時間排序

find . -path '*/.git' -prune -o -type f -newermt "$(date +%F)" \
     -printf '%TY-%Tm-%Td %TH:%TM  %10s  %p\n' | sort

避免用 %TT：它會印出 22:37:52.8339704510 這種帶十位小數秒的時間，難讀。

A''. 排除 log 雜訊

find . \( -path '*/.git' -o -path '*/log' -o -name '*.log' \) -prune -o \
     -type f -newermt "$(date +%F)" -print | sort

A'''. 只列某種副檔名（例：*.md）

# 只要 .md
find . -path '*/.git' -prune -o -type f -name '*.md' -newermt "$(date +%F)" -print | sort

# 大小寫都收（.md / .MD / .Md）
find . -path '*/.git' -prune -o -type f -iname '*.md' -newermt "$(date +%F)" -print | sort

# 多種副檔名：用 \( ... -o ... \) 包起來
find . -path '*/.git' -prune -o -type f \( -name '*.md' -o -name '*.html' \) \
     -newermt "$(date +%F)" -print | sort

實測（同一棵樹、同一時段）：-name '*.md' 135 個、-iname '*.md' 135 個（這棵樹沒有大寫副檔名）、.md ＋ .html 138 個。

兩個常見錯誤

1. '*.md' 一定要加引號。沒加的話，shell 會在目前目錄先把它展開，find 就會回 paths must precede expression（見 find / rm 參考卡 第 01 節）。

2. 多個副檔名一定要用括號包起來。find 的 -a（隱含的 AND）優先序高於 -o。沒有括號時，-type f -name '*.md' -o -name '*.html' -newermt ... -print 會被解讀成 (-type f -a -name '*.md') -o (-name '*.html' -a -newermt ... -a -print)，-print 只綁在最後一個分支上，.md 全部消失。實測：加括號 138 個，不加只剩 3 個（＝今天的 .html）。而且因為命令裡已經有明確的 -print，find 不會替 .md 那個分支補上預設的 print，所以這個錯誤不會報錯，只會安靜地少列。括號本身也要跳脫成 \( \)，否則會被 shell 當成 subshell。

套用到其他口徑的寫法一樣：B 在 -newermt 前面加 -name '*.md'；C 在結尾接 | grep '\.md$'。

B. 今天出生的（birth，GNU find 可用的替代寫法）

T=$(date -d "$(date +%F)" +%s)
find . -path '*/.git' -prune -o -type f -newermt "$(date +%F)" \
     -exec stat -c '%W %n' {} + | awk -v t="$T" '$1>=t{sub(/^[0-9]+ /,""); print}' | sort

先用 mtime 縮小候選範圍（今天出生的檔案，mtime 一定也在今天），再用 stat %W（epoch 秒）過濾。sub() 只拿掉開頭的數字，所以含空白的檔名不會被截斷。

限制

檔名含換行時這條管線會斷行。另外，被 atomic rename 重寫過的舊檔也會被列進來（見第 03 節對照組）。

C. 今天第一次進版控的（語意最準）

# 今天已 commit 的新檔 + 尚未追蹤的新檔
{ git log --since=midnight --diff-filter=A --name-only --format=; \
  git ls-files --others --exclude-standard; } | sort -u

# 巢狀 repo 要逐一跑（父 repo 看不到它們）
for r in */; do [ -d "$r.git" ] && git -C "$r" log --since=midnight --diff-filter=A --name-only --format= | sed "s#^#$r#"; done

怎麼選

情境用哪條
想知道今天動過哪些東西（最常見）A ／ A'
今天的產出被 daemon log 淹沒A''
只要某種副檔名（如今天寫的筆記 *.md）A'''
要找今天新建的、而且不在版控裡B（接受 rename 誤收）
要找今天新增的「作品」C
一行版總結

日常用 find . -path '*/.git' -prune -o -type f -newermt "$(date +%F)" -print。要找「新建」的就別信 birth time，改問 git。

06附錄
